# THE ASSERTIONS THIS SUITE IS PERMITTED NOT TO MAKE, AND WHY EACH ONE CANNOT CARRY A BOUND.
#
# Read by `tools/harness_verdict.sh` on a full sweep. Columns, TAB-separated:
#
#     <id>	<layer>	<always|env>	<why no bound can responsibly be set>
#
# `id` is what `_stand_down()` prints in brackets. `always` means the layer may not run without standing
# this down; `env` means it is permitted but conditional on the machine or the run.
#
# WHY THIS FILE EXISTS. A full sweep with a display cannot reach exit 0 and never will, because these
# stand-downs are structural. That makes "the full sweep is green" an unreachable gate, and an unreachable
# gate is met by deleting an honest stand-down or inventing a bound nobody earned. The reachable, checkable
# target is: EXIT 4, WITH EXACTLY THESE AND NO OTHERS.
#
#   an id appears that is not listed here          RED. Nobody quietly stops asserting something.
#   an `always` id is absent and its layer RAN     RED. The list must be tightened when a debt is paid.
#   a registered layer did not run at all          EXEMPT, and NAMED in the verdict.
#
# THE THIRD RULE IS THE ONE THAT COST TWO REWRITES. The first registry keyed on (layer, count) and would
# have failed CI's headless job with a diagnosis that was wrong: three of these layers need a display, so
# headless they whole-layer SKIP, and `${_got:-0}` scored "never ran" as "ran and stood down zero". The gate
# would have reported a debt paid and recommended tightening the list -- which would have deleted three
# real entries. A missing measurement read as a measured zero: the same root as every other finding on this
# branch, this time surfacing as a loud wrong red rather than a quiet green, which is luckier and not
# better. Found by c1 from the job matrix; confirmed here by running the sweep headless.
#
# AND THE COUNT KEY COULD NOT HAVE WORKED ANYWAY. It cannot tell "an assertion is now being made" from "a
# different machine took a different branch" -- `check_frametime` returns early on an unset SF_PERF_HOST,
# making its second site unreachable, so both present as 2 -> 1. Ids make the environment change legible:
# the set membership moves, and each member says what it is.
#
# EVERY POSSIBLE STAND-DOWN IS LISTED, not only the ones seen firing, so that this file is the complete
# list of assertions this suite may decline to make. Ones marked `env` have conditions that did not hold on
# the runs it was written from; they are permitted, not verified.

frametime.absolute-budget	check_frametime	iff:perf-host-unset	The 8.33ms (120fps) budget asserts only when SF_PERF_HOST names the machine, and it is set nowhere. A frame-rate claim on arbitrary hardware is a statement about the box. `env` because setting SF_PERF_HOST makes this one vanish and the paced one below possible.
frametime.paced-phase	check_frametime	env	A vsync-paced p95 inside the budget cannot tell a fast phase from a pinned one, so it is reported and not banked. Unreachable while SF_PERF_HOST is unset, because _absolute() returns before the loop.
grapple.gr05-preview-share	check_grapple_reads	always	GR-05's share of the throw the preview inks. The cap that stood here was 1.01 over a quantity `_corridor_fill` bounds at 1.0 BY CONSTRUCTION -- an assertion that could not fail. Removing it was right; what is owed is a design call, not a guessed bound.
grapple.gr03-single-frame-bow	check_grapple_reads	env	GR-03's single-frame bow, floor and taut-against-slack ratio. Neither number came off the cord, so a verdict would be a claim about the instrument wearing the rope's name. PROBABLY MISFILED AS A STAND-DOWN: it fires when _bow_measured reports the number came off the mask's rim rather than the cord, which is INSTRUMENT SATURATION -- the layer ran, tried to measure its subject, and the sample was spoiled. That is this repository's definition of VOID, near enough word for word. A stand-down says no bound can responsibly be set and a design decision is owed; a VOID says this sample is spoiled, run it again. Those ask opposite things of a reader. c1's reading; left as-is because changing a layer's verdict semantics is a decision, not a cleanup, and it has never fired.
ceremony.words-vs-sky	check_ceremony_reads	always	How well the words read against open sky. The arm now carries a drift floor measured inside its own run, so the reading has something in its own units to be a ratio against; the missing piece is the distribution across several runs.
ceremony.rope-share	check_ceremony_reads	always	How much of the rope an interrupt may take. No design decision exists about what the ceremony owes the world it interrupts, and the layer's own note is that a bound guessed before that decision has been wrong four times in this repository.
ceremony.words-vs-sky-arm	check_ceremony_reads	env	The control arm of the same reading, stood down on the runs where the arm itself could not be measured.
contrast.bright-backdrop	check_text_contrast	always	A lane boundary: how much light the world puts through a 0.90 plate is a property of the renderer, not of the palette, and this layer's lane is the palette.
contrast.wash-and-brass	check_text_contrast	always	A REAL gap, not a lane boundary. The wash tiles and the picked row's brass are literals in the drawing code rather than named constants, so no row here can reference them. Measured by hand once and cleared; nothing re-measures them on the next edit. Priced by the layer at ten drawing sites.
dig-hitch.byte-identity	check_dig_hitch	iff:no-display	Byte-identity of the rebaked region, headless only: the dummy driver returns a blank image, so the comparison cannot fail and asserting it would be a lie. Extent and cost still assert. This one is invisible to any sweep run WITH a display, which is why a registry built from display runs did not know it existed.
save-durability.failed-backup	check_save_durability	env	HIGHEST-STAKES ROW IN THIS FILE, AND UNMEASURED ON THE PLATFORM THAT MATTERS. It fires when the platform lets copy_absolute write onto a directory, which is the forcing function for the whole failed-backup path. On macOS the copy fails, so the path IS exercised and this never fires. It has NEVER RUN ON LINUX -- check_save_durability is a plain `add`, so CI executes it with different filesystem semantics, and if copy_absolute behaves differently there the backup-abort assertions stop being made in CI permanently, silently, green. That is the guard whose failure costs a person their data. WHAT TO DO: the first Linux CI run after this lands answers it -- grep the job log for [save-durability.failed-backup]. Present means the path is unexercised on Linux and this needs a platform-independent forcing function, not a registry row. Absent means macOS and Linux agree and this row can be deleted. Raised by c1, who also noted it is the one thing here that wants a measurement rather than a reading.
bindings.file-order-control	check_binding_persistence	env	MISLABELLED, AND KEPT HERE UNTIL SOMEBODY DECIDES WHAT IT SHOULD BE. Its condition is ConfigFile returning the same key order for both writes, which is DETERMINISTIC for a given engine build and key set, not environmental -- it will always fire or never fire on a given version, not sometimes. `env` is describing a coin that is actually a constant. Today it never fires and the precedence control works; one engine update and that control is permanently dead with nothing saying so. c1's reading.
